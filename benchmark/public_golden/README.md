# Public golden corpus

This corpus makes conversion regressions visible in a clean checkout. It
contains **3 redistributable PDFs, 5 conversion cases, 8 selected pages and 53
manually reviewed checks**. The source rights and modification notes are in
[`ATTRIBUTION.md`](ATTRIBUTION.md). The third-party PDFs are reproduced
unchanged; no personal or commercial samples are included.

The checks are *focused golden probes*: each expected phrase, role, order,
table span or image requirement was read from the rendered PDF. They are not
full transcriptions of every page, and the committed Docling JSON is not used
as ground truth. The runner checks the PDF SHA-256 before using an annotation,
so a changed source must be reviewed again. The fast gate also pins a digest
of **every** semantic block, note and table cell from each snapshot. That
digest detects unreviewed changes outside the 53 hand-written probes; it is a
change detector, not a correctness score. Raster bytes are excluded so the
semantic baseline can run on macOS and Linux. Fresh Docling runs use focused
content checks because model inference can merge adjacent paragraphs
differently across platforms.

| Case and PDF pages | What is gated | Known gaps |
| --- | --- | --- |
| `layout-stress`, 1 | Two-column markers, title levels, list, exact indented code, literal XML characters, merged header, figure/caption, note, furniture removal | Right-column heading appears too early; table values have wrong column association; note is not linked. |
| `ods-toc`, 4 | Printed contents remain visible as a sharp source crop in the EPUB | Printed entries are not searchable links. |
| `ods-tables-footnote`, 35–36 | Section titles, two tables, header spans, selected cells, caption, URL note, furniture removal | Some inline math is damaged; table-note markers are not linked. |
| `ods-figure-code`, 101–102 | Diagram, caption, title, three visually preserved code blocks, order, furniture removal | Code uses image fallback; diagram caption is a separate block. |
| `joss-figure-list`, 1–2 | Title, section titles, four ordered steps, scientific diagram/caption, order, footer removal | Decorative marks become figures; author line is split. |

All five cases also build and validate an EPUB 3, verify every referenced asset
is packaged, and compare two builds with a fixed timestamp byte for byte. The
synthetic case additionally runs the public CLI with its default PDF cover. The
fixtures deliberately include current defects in `known_gaps`; passing CI
means the **gated properties** still hold, not that all visible content is
perfect. Fix a gap by adding a mandatory check from the reviewed page, then
removing its entry from `known_gaps`.

## Run locally

Fast gate, using the committed native Docling snapshots:

```bash
python -m pip install -e .
python benchmark/public_golden/run.py
```

Full gate, extracting the same licensed PDFs afresh:

```bash
python -m pip install -e '.[convert]'
python benchmark/public_golden/run.py --live
```

`--case layout-stress` selects one case. The `tests/` suite runs the fast gate;
the `public-golden-live` GitHub Actions job runs the full gate on each push and
pull request. Live extraction downloads Docling models on the first run and
uses CPU with OCR disabled. Snapshots are gzip files generated with Docling
2.128.0, `standard`, `--no-ocr`, `--table-mode fast`, and embedded images.
They contain only the selected page ranges. All generated EPUBs and temporary
files are disposable and stay outside Git.

The synthetic source PDF is generated by `generate_synthetic.py` using
ReportLab (`invariant=1`). ReportLab is a developer-only dependency: CI reads
the committed PDF and does not regenerate it. After changing the generator,
regenerate and render the PDF, review every page, update its checksum and
annotation, then refresh the Docling snapshot.

## Adding a case

1. Choose a document whose license explicitly permits redistribution and
   derivatives; record the author, original URL, license URL, and any changes
   in `ATTRIBUTION.md`.
2. Commit the exact PDF, pin its SHA-256 in `manifest.json`, and select a small
   but demanding page range. Keep extracted text/images inside this documented
   corpus only.
3. Render the selected pages. Write `annotations/<case>.json` from the visible
   page, with checks that distinguish a correct EPUB from a plausible but wrong
   one. Record unresolved defects as `known_gaps`.
4. Generate a native JSON snapshot with the documented Docling options, gzip
   it with timestamp zero, and run both gates. A second reviewer should compare
   the annotation with the rendered page before increasing thresholds.

Next coverage targets are isolated formulas, rotated pages, three-column
reading order, right-to-left text, scans requiring OCR, nested tables, and
long-document performance. No finite corpus can prove correctness for every
PDF. Add a new licensed fixture and failing check whenever a new failure mode
is found.
